`Dialog` is the modal composition for short, focused decisions and transient tasks. Radix provides the modal interaction model; Augur owns the API shape, surface roles, geometry, spacing, and documentation contract.

## When to use

- A confirmation or short task needs full attention before the underlying flow continues.
- The content is transient and self-contained: open, act or decide, close.
- Focus should be contained in the modal layer while it is open.
- One clear primary action and supporting actions fit within a compact panel.

## When not to use

- Do not use Dialog for passive supplementary content that can stay inline or in a lighter disclosure.
- Do not use it when people need persistent page context while deciding.
- Do not stack dialogs; restructure the flow instead.
- Do not move a long-running workflow into a modal merely to reduce page complexity.

## Variants

Dialog has one visual treatment and two primitive behavior modes:

| Mode | Prop | Behavior |
| --- | --- | --- |
| Modal | `modal` omitted or set to `true` | Scrim, scroll lock, focus containment, outside dismissal |
| Non-modal | `modal` set to `false` | Page interaction remains available; advanced composition owns overlay behavior |

The starter documentation focuses on the modal form.

## Sizes

| Size | Width | Typical use |
| --- | --- | --- |
| `sm` | 24rem | Confirmation or one short decision |
| `md` | 32rem | Standard short form or review |
| `lg` | 40rem | Longer modal content |

All sizes are capped at `100vw - 16px`. Panel height is capped to the viewport and scrolls internally when needed.

Dialog uses a 24px panel inset on larger viewports and 16px below 600px. Panel and close-control radius are 0px. Coarse-pointer close controls expand to 44×44px.

## States

- **Open:** panel and scrim appear immediately; Augur adds no decorative opening animation.
- **Focus:** focus moves into the panel, remains contained while modal, and restores to the trigger on close.
- **Dismissal:** Escape, overlay press, close control, or a composed `DialogClose` action closes the modal.
- **Hover:** the close control uses the semantic neutral highlight surface.
- **Theme:** the panel uses the semantic floating-layer pairing and can inherit a scoped theme through an explicit portal container.

## Accessibility

- Dialog content must have an accessible name through `DialogTitle`, `aria-label`, or `aria-labelledby`.
- `DialogDescription` is recommended and wires descriptive context when present.
- Focus containment/restoration comes from the primitive rather than a custom focus-trap implementation.
- Escape provides keyboard-equivalent dismissal for the overlay path.
- Scoped theme consumers should provide the correct portal container so the modal inherits the subtree's semantic roles.
- Reduced-motion preferences remain respected even though the current Augur treatment is immediate.

## API

```tsx
import {
  Dialog, DialogTrigger, DialogPortal, DialogOverlay, DialogContent,
  DialogHeader, DialogFooter, DialogTitle, DialogDescription, DialogClose,
} from "@augurproject/design-system";
```

| Part | Purpose |
| --- | --- |
| `Dialog` | Root state and modal behavior |
| `DialogTrigger` | Opens the dialog |
| `DialogPortal` | Portal placement |
| `DialogOverlay` | Modal scrim |
| `DialogContent` | Dialog panel; supports `size` and portal `container` |
| `DialogHeader` / `DialogFooter` | Composition regions |
| `DialogTitle` | Accessible dialog name and heading |
| `DialogDescription` | Supporting descriptive copy |
| `DialogClose` | Closes the dialog from inside the composition |

Use `open` + `onOpenChange` for controlled state or `DialogTrigger` / `defaultOpen` for uncontrolled usage. Native props and React 19 refs pass through the parts.

## Design rationale

Dialog delegates complex modal behavior to a proven primitive while keeping visual decisions in Augur. Its surface sits one tonal step above normal cards, uses square geometry, and avoids decorative motion so the modal's interruption is communicated by behavior and layering rather than animation.

## Related components and patterns

Use [Button](/components/button) for dialog actions. Prefer inline page composition or a future non-modal disclosure when the user needs surrounding context while acting.

## Verification
