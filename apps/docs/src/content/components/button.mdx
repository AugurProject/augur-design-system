## When to use

- Use `default` for the primary action in a coherent task area.
- Use `secondary`, `outline`, or `ghost` for supporting actions.
- Use `link` for an action that should read as inline text while still behaving like a command.
- Use `destructive` for a high-consequence action, with a label that names the consequence directly.

## When not to use

- Do not use a `<button>` for navigation between pages; use a link. When the link needs button styling, render it through `asChild` (below).
- Do not use it as a selected/on-off control; Button does not own choice semantics.
- Do not multiply `default` actions until several controls compete for the same priority.
- Do not rely on an icon alone when a short action label can make the command clearer.

## Variants

| Variant | Role | Use |
| --- | --- | --- |
| `default` | `--primary` / `--primary-foreground` | Primary action and default green-intent carrier |
| `secondary` | semantic secondary pairing | Supporting action |
| `destructive` | semantic destructive pairing | High-consequence action; copy names the consequence |
| `outline` | transparent + `--input` edge | Supporting action on an existing surface |
| `ghost` | transparent | Lowest-emphasis button action |
| `link` | text only | Inline command-like action |

On hover, filled variants step to a neighboring palette color in their own family: `default` moves from Deep to Green in light and from Green to Wash in dark, both with a Navy label; `secondary` and `destructive` step one tone along their own surface ramp. `outline` and `ghost` step onto the semantic neutral highlight surface, and the `outline` edge strengthens to `--input-hover`. Every non-link variant uses a strong neutral inversion while pressed. The `link` variant gains an underline. Hover does not introduce a second green treatment.

## Sizes

| Size | Height | Horizontal padding |
| --- | ---: | ---: |
| `sm` | 32px | 12px |
| `md` | 36px | 16px |
| `lg` | 40px | 24px |

These are the maintained structural control sizes. On coarse pointers, the actionable target expands to at least 44×44px without redefining the desktop size labels.

## States

- **Hover:** a neighboring palette step for filled variants (`--primary-hover`, `--secondary-hover`, `--destructive-hover`); the neutral highlight surface for `outline` and `ghost`, plus the `--input-hover` edge on `outline`; underline for `link`.
- **Pressed:** strong neutral inversion for standard variants.
- **Focus:** shared 2px `:focus-visible` ring with a 2px offset from `--ring`.
- **Disabled:** native `disabled`, non-interactive, label remains present, `cursor: not-allowed`, reduced opacity.
- **Loading:** non-interactive with `aria-busy="true"`; the visible label keeps its width while a centered static pending indicator and accessible loading status take over.

## Links with button styling

A call to action that navigates is a link, even when it looks like a button. Pass `asChild` and a single link child: Button merges its classes onto the link and renders nothing else, so the element keeps link semantics, `href`, and native link behavior (Enter follows it; screen readers announce a link).

```tsx
<Button asChild>
  <a href="/protocol/">How Augur works</a>
</Button>
```

`type`, `disabled`, and `loading` describe button behavior and are not accepted with `asChild`. A link has no disabled state; remove it or explain why the destination is unavailable.

Static and non-React consumers apply the same classes to an `<a>` with `buttonVariants()`. Importing `buttonVariants` also imports the component stylesheet, so the classes resolve without the React component. The stylesheet's margin reset has zero specificity, so layout margins set by the consumer always apply.

## Accessibility

- Native `<button>` semantics provide Tab, Enter, and Space behavior without invented ARIA.
- `type` defaults to `button`; form submission is an explicit `type="submit"` choice.
- Write specific verbs: `Open record`, `Save changes`, `Delete proposal`, not `OK`.
- Loading exposes busy state and an accessible status without shifting the control's geometry.
- Focus comes from the shared interaction contract and remains visible in both themes.
- Coarse-pointer contexts preserve at least a 44×44px actionable target.

## API

```tsx
import { Button, buttonVariants } from "@augurproject/design-system";
```

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `"default" \| "secondary" \| "destructive" \| "outline" \| "ghost" \| "link"` | `"default"` | Action hierarchy |
| `size` | `"sm" \| "md" \| "lg" \| "xl"` | `"md"` | Structural control size; `xl` is 48px with 16/24 labels |
| `loading` | `boolean` | `false` | Stable-width busy state |
| `disabled` | `boolean` | `false` | Native disabled state |
| `type` | `"button" \| "submit" \| "reset"` | `"button"` | Native button type |
| `asChild` | `boolean` | `false` | Merge the button classes onto the single child element (typically a link) instead of rendering a `<button>` |
| `className` | `string` | — | Extends the component classes |
| `ref` | `React.Ref` | — | Ref for the underlying button element |
| …props | native button attributes | — | Passed through to the native element |

`buttonVariants({ variant, size })` returns the component class string for class-only or registry-path consumers. In registry installs, `button-variants.ts` imports `button.css`, so class-only use gets the styles.

## Design rationale

Button keeps command semantics native and the visual API deliberately small. Semantic roles allow the same hierarchy to survive both themes without color props or local token maps.

The default action carries the primary intent signal; supporting variants remain neutral. Destructive meaning is carried by explicit language because the brand palette does not introduce a separate danger hue.

## Related components and patterns

Use Button inside [PageHeader](/patterns/page-header), [Card](/components/card), [Dialog](/components/dialog), and [EmptyState](/patterns/empty-state) when those compositions need actions. The containing pattern owns placement; Button owns the command.
