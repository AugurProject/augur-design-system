`Card` is a grouping surface. It uses the semantic card pairing, a perceivable hairline edge, square geometry, and composition spacing. It does not imply record state, clickability, or product meaning.

## When to use

- Group content that should read as one panel.
- Keep related metadata, supporting copy, and local actions together.
- Use a card when a tonal panel improves grouping more than open page composition would.

## When not to use

- Do not wrap every section in a Card by default; open composition is preferred when spacing and headings already make the grouping clear.
- Do not use a Card as a modal or floating layer; use Dialog or another disclosure pattern.
- Do not use the container itself to mean Open, Closed, Pending, selected, or clickable.
- Avoid card-inside-card nesting unless a future pattern documents a concrete need for another surface step.

## Variants

Card ships one surface treatment. Different compositions come from the presence or absence of header, description, content, and footer parts rather than from visual variants.

## Sizes

Card width is owned by the surrounding layout and height by its content.

The standard panel inset is 24px and steps to 16px below 600px. Title-to-description and footer-action gaps use the maintained local spacing scale. Card uses the encoded square surface radius: 0px.

## States

Card has no interactive container state. It renders a plain `div` with no hover, focus, pressed, disabled, or loading behavior.

Interactive children keep their own contracts inside the Card.

## Accessibility

- Card itself is a composition `div`, not a landmark or button.
- `CardTitle` renders an `h3`; consumers remain responsible for placing it at a sensible document-outline depth.
- `CardDescription` is supporting copy and must not carry required information by itself.
- Interactive children remain separate semantic controls, so keyboard and screen-reader behavior does not depend on the container.

## API

```tsx
import {
  Card,
  CardHeader,
  CardTitle,
  CardDescription,
  CardContent,
  CardFooter,
} from "@augurproject/design-system";
```

| Part | Element | Purpose |
| --- | --- | --- |
| `Card` | `div` | Grouping surface |
| `CardHeader` | `div` | Title/description stack |
| `CardTitle` | `h3` | Panel title |
| `CardDescription` | `p` | Supporting line |
| `CardContent` | `div` | Main content |
| `CardFooter` | `div` | Local action row |

Every part accepts native attributes for its element, `className`, and a React 19 ref prop.

## Design rationale

Card uses tonal grouping and a hairline edge rather than shadow or rounded depth. The 0px radius is the shared surface rule, not a Card-specific aesthetic choice.

A Card should earn its boundary. If the page hierarchy works without a panel, use the simpler composition.

## Related components and patterns

Use [Button](/components/button) for Card actions. Use [Dialog](/components/dialog) when content must interrupt the page as a modal layer. Use [PageHeader](/patterns/page-header) for page-level hierarchy rather than nesting a page header inside a Card.
