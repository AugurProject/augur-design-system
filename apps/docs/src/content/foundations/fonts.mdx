Augur uses two sans-serif families with distinct responsibilities. **Sora** is the primary voice for identity, display, headings, controls, key actions, and primary navigation. **Schibsted Grotesk** is the supporting voice for paragraphs, helper text, metadata, tables, and dense UI text.

Families are not alternated for decoration. Each text element should have a clear role in the hierarchy.

## Two voices. Clear roles.

Sora leads. Schibsted Grotesk supports. Size creates order; weight confirms it.

## Editorial and interface hierarchy

Augur uses regular-weight editorial roles alongside stronger interface roles:

- `editorial-title` and `editorial-section` use Sora 400 so scale can establish hierarchy without unnecessary weight;
- display, heading, and control roles retain their stronger interface hierarchy;
- `editorial-label` uses tracked Schibsted Grotesk for short metadata-like labels;
- body, helper, table, and record text stay in the supporting voice.

Do not globally reduce interface heading weights to imitate editorial pages. Choose the role that matches the content's job.

## Writing and data conventions

Use sentence case for headings, controls, and labels. Reserve capitals for short metadata and standard abbreviations.

Do not stack size, weight, color, and capitals to manufacture hierarchy. One strong distinction and one secondary distinction are usually enough.

For tables and records:

- align numeric columns right;
- use one precision per view;
- put units in a column header or beside the value;
- preserve recognizable prefixes and suffixes when long technical strings must truncate.

## Loading behavior

```ts
import "@augurproject/design-system/styles.css";
```

The stylesheet brings the pinned Sora 400/600 and Schibsted Grotesk 400 font files into the consumer bundle. Font files are self-hosted; no font CDN or third-party request is required.

`--augur-font-primary` and `--augur-font-secondary` provide the maintained family stacks so text remains readable while faces load.

## Source code in documentation

Documentation shows source code (fenced blocks, inline identifiers, and example source) in the platform monospace stack, because code depends on fixed-width alignment. The monospace stack is documentation chrome, not a third Augur voice: product interfaces set technical strings such as addresses and identifiers in Schibsted Grotesk, as described above. Long-form documentation prose uses the adopted body role, 16/24.
