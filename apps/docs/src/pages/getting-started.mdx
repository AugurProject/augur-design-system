Choose the consumption path that matches your application, load the shared styles, then use the foundations to make hierarchy and behavior decisions before composing components.

## Choose a consumption path

### Source registry

Registry items are generated from canonical package sources and published under `/r/`. Start with `augur-theme`, then add the components or patterns the application needs. Pin a verified repository ref for reproducible consumption rather than treating `main` as a release channel.

Once you have the resolved item URL, use the standard shadcn source-install command:

```sh
npx shadcn@latest add "$REGISTRY_ITEM_URL"
```

The design-system repository remains the authority for which registry items and refs are valid.

### Workspace package

Applications in this workspace can import the package directly:

```tsx
import { Button, Card, Input } from "@augurproject/design-system";
import "@augurproject/design-system/styles.css";
```

The aggregated stylesheet delivers self-hosted fonts, generated tokens, semantic light/dark roles, typography roles, shared focus behavior, and the system's structural styling.

## Theme behavior

Light and dark are equal everyday themes. With no explicit theme, the system preference governs. Pin a theme with `data-theme="light"` or `data-theme="dark"` on the document or a subtree.

See [Theming](/foundations/theming) for the selection and scoping contract.

## Current starter set

The documented component starter set is Button, Card, Input, and Dialog. Reusable compositions include FormField, PageHeader, and EmptyState.

Reference Record is retained as a source-grounded reference composition. Treat it as evidence for record-language decisions, not as a default product workflow.

## Authority and further reference

`DESIGN.md` owns adopted design values representable by the pinned schema. Generated token outputs are derived artifacts. Foundation documentation owns maintained design guidance that does not fit the schema cleanly, while component and pattern pages own usage, behavior, and composition decisions.

For package and export details, see [Package entries](/reference/package-entries). For contribution and verification rules, see [Contributing](/reference/contributing).
